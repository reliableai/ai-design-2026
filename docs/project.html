Course Project

Build and evaluate a large-scale AI system (Weeks 6-12)

Overview

The course project is the capstone experience of this course. You'll apply everything you've learned to design, implement, and rigorously evaluate an AI-powered system. Projects can be done individually or in teams of two.

Track Options

Track A: Class System

Work on a shared class project with a well-defined scope and requirements. We work together in class: reviews, working sessions, design clinics, and rehearsals.

  • Teams of 1–2 students
  • Pre-defined problem space with shared baseline
  • In-class reviews and working sessions (Weeks 7–11)
  • Exam: presentation + discussion

Track B: Capstone (Individual)

Propose your own project idea. The instructor approves the scope, then you work independently. Track B projects are individual only.

  • Custom problem definition, must be approved by instructor
  • Full system design responsibility
  • Independent work — no in-class reviews
  • Exam: presentation + detailed discussion of your design decisions, evaluation, and results

Example projects from previous students

  • AI-Workflows — evaluation framework for AI-powered workflow generation, comparing monolithic, incremental, and bottom-up strategies
  • Tool Calling Optimization — measuring LLM tool-calling accuracy across retrieval methods (MCP, clustering, RAG, adaptive RAG)

Project Requirements

System Requirements

  • Functional AI-powered application with clear use case
  • Integration of agents, tools, and/or memory systems
  • Appropriate error handling and logging
  • Basic observability (metrics, logs)
  • Safety considerations and guardrails where appropriate

Evaluation Requirements

  • Golden Dataset: Curated test set with ground truth labels
  • Metrics: Well-justified selection of evaluation metrics
  • Experiments: At least one ablation study or comparative experiment
  • Error Analysis: Systematic categorization of failure modes
  • Uncertainty: Confidence intervals or other uncertainty measures

Deliverables

Both tracks: Exam

The exam for both tracks is a presentation followed by a discussion. You present your system, design choices, evaluation, and results, then answer questions.

Both tracks: Final deliverables

  • Presentation + discussion — system demo, design choices and alternatives, evaluation results, limitations
  • Report — problem statement, architecture, experiments, results, error analysis, lessons learned
  • Code repository — documented source, README with setup instructions, evaluation scripts, golden dataset

Track A: In-class milestones

  • Week 6: Project spec v1 — problem statement, architecture sketch, evaluation plan, team formation
  • Week 7: Review #1 — refined scope, detailed architecture, golden dataset status
  • Weeks 8–10: Working sessions — implementation, evaluation runs, design clinics
  • Week 9: Mid-project presentation (10–12 min internal demo)
  • Week 11: Results review and presentation rehearsal
  • Week 12: Final presentation + discussion (graded)

Track B: Independent milestones

  • Week 6: Scope proposal — submit problem statement and high-level plan for instructor approval
  • Weeks 7–11: Independent work
  • Exam session: Presentation + detailed discussion (graded)

Timeline (Track A)

Track B students submit their scope proposal in Week 6 and work independently until the exam.

Team Formation (Track A only)

  • Teams of 1–2 students
  • Both team members must contribute equally and be able to present any part
  • Define clear responsibilities early

For 2-person teams, consider dividing work along these lines:

  • System Lead: Architecture, implementation, integration
  • Evaluation Lead: Golden dataset, metrics, experiments, analysis

Track B is individual — no teams.

Grading Rubric (0–30)

Both tracks use the same rubric. Each dimension is scored 0–10.

Dimension (0–10 each) What we look for
Design & Prototypes Clear goals, meaningful design alternatives, working prototype(s) that reflect the design choices
Experiments & Analysis Experiments comparing variants, appropriate metrics, honest analysis of results and failures, reflection on limitations
Communication Well-structured presentation and report, clear explanation of choices and lessons learned, good Q&A
